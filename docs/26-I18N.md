# 26 · Interface language (English / 中文)

Added in R21. Every page (admin console, kiosk, visitor invitation, self check-out,
calendar confirmation, signup, evidence pack, printable visitor list) can be shown
in **English or Simplified Chinese**. Server messages are still English; see
[Limitations](#6-limitations).

## 1. For users

- **Choosing the language.** The first visit follows the browser language (`zh-*` → Chinese,
  anything else → English). The **中文 / English** button (admin: in the header next to
  the sign-in status; other pages: top right) switches and remembers the choice on
  that device.
- **Links.** Add `?lang=zh` or `?lang=en` to any page URL to force a language, for
  example on the reception tablet: `https://doors.example.com/kiosk?lang=zh`. The
  choice is remembered on that device as well.
- **Dates and times** follow the language (`2026/9/27 18:30` in Chinese). Times are
  still shown in the door's time zone, as before.
- **Names stay as typed.** Door, group, person and site names, door codes, tokens
  and audit details are not translated (unless a name is exactly a UI word; see §6).

## 2. How it works

Two static files, loaded first on every page (before the page's own scripts):

| File | What it is |
|---|---|
| `public/i18n-zh.js` | The dictionary: `window.AX_I18N_ZH = { text, patterns }`. `text` maps an English UI string (whitespace-normalised) to Chinese; `patterns` are `[/^…$/, replacement]` pairs for sentences with numbers or names in them. |
| `public/i18n.js` | The engine. Picks the language, sets `window.axLang` (`'en'`/`'zh'`) and `window.axLocale` (`'zh-CN'` or `undefined` = browser default), exposes `window.axT(s)`, adds the switch button. |

The pages keep their English source. When the language is Chinese the engine:

1. translates every text node and the `placeholder`, `title`, `aria-label`, `alt`
   attributes (and button `value`s) by **whole-string** lookup: exact entry first, then
   the patterns in order; misses are cached;
2. keeps translating whatever is rendered later (a `MutationObserver` on the whole page);
3. translates `alert` / `confirm` / `prompt` messages and the page title, and sets
   `<html lang="zh-CN">`;
4. skips anything inside `translate="no"`, `script`, `style`, `textarea`, `code`.

Why this design and not keys in the source: the UI is ~1,150 lines of template
strings in `app.js` plus seven smaller pages. Rewriting every string as `t('key')`
would have touched almost every line a week before the first pilot. The overlay
leaves the English code path untouched (with English selected, the engine only
adds the button), and a missing Chinese entry degrades to English instead of a key.

Dates: code that formats dates passes `window.axLocale` to `toLocaleString` /
`Intl.DateTimeFormat` (24 call sites in `app.js`, `invite.js`, `visitors-print.js`,
`evidence.js`). Time-zone abbreviations (`AEST`) stay English on purpose.

Content Security Policy is unchanged (`script-src 'self'`): both files are static
same-origin scripts; the button's inline style is set through the CSSOM, which CSP
allows. The service worker (`sw.js`, cache `axess-v28`) caches both files.

## 4. Adding or changing UI text

1. Write the English string in the page as usual.
2. Add the Chinese to `public/i18n-zh.js`:
   - plain strings go in `text`, keyed by the **exact visible text with whitespace
     collapsed** (what the user sees, not the template source);
   - strings with a number or a name in them go in `patterns`: anchor with `^…$`,
     **no `g` flag**, keep the pattern narrow (a pattern such as `^to (.+)$` once turned
     the checklist tag "to do" into "到 do"). A function replacement can call
     `T(part)` to translate a sub-phrase;
   - a user-supplied name that happens to equal a UI word would be translated, so
     wrap such values in an element with `translate="no"`;
   - when the Chinese needs a different word order than the English fragments allow,
     build the string in code with `window.axLang === 'zh' ? … : …` (see the door
     group "Move… / to …" menu in `app.js`).
3. Run `npm test`. `test/i18n.test.js` fails if a string in any static HTML page has
   no translation, a key is not whitespace-normalised, a value has no Chinese, a
   pattern is unanchored or has a `g`/`y` flag, a translation would be translated
   again (the observer would loop on its own writes), or a page loads the scripts in
   the wrong order.
4. For dynamic text (rendered by JavaScript), run the coverage tool:

   ```sh
   npm i --prefix /tmp/jsd jsdom@24          # once; jsdom is not a project dependency
   JSDOM=/tmp/jsd/node_modules/jsdom node --no-warnings support/i18n-coverage.js \
     [--json out.json] [--dump zh.txt]
   ```

   It boots the Node server with demo data, renders all eight pages and all six admin
   tabs in Chinese, and lists every English string still visible, with the pages it is
   on. `--dump` writes every Chinese string it saw, for proofreading. Demo data names
   (from `data/acl.json`, `data/mirror.json`, the demo locks), ids and the strings in
   `support/i18n-keep.js` are not counted.

After R21: default states **100% Chinese (3,668 visible strings, 0 English)**, 565
dictionary entries and 27 patterns.

## 5. Adding another language

Copy `i18n-zh.js` to `i18n-<code>.js` with `window.AX_I18N_<CODE>`, then in
`i18n.js` add the code to `NAMES`, map it in the `dict` and `axLocale` lines, and
extend the browser-language check. Load the new file on each page next to the
Chinese one and add it to `sw.js`. The switch button currently toggles between two
languages; with three it should become a small menu.

## 6. Limitations

- **Server messages are English:** API error texts shown as-is, copilot answers,
  emails, SMS, calendar mails, alert webhooks, CSV/JSON exports, the evidence pack's
  control names (ISO/IEC 27001, SOC 2 identifiers stay as the standards write them).
  A tenant language setting on the server is in the backlog.
- **Whole-string matching:** a sentence split across several elements (for example a
  label, a bold value and a trailing hint in separate tags) is translated piece by
  piece, so the Chinese word order can be stiff. The important ones are covered by
  patterns or built in code.
- **Coverage is measured on the default state of each page.** Messages that appear
  only after an action (success banners, some validation texts) are covered where the
  string was known from the source, but not all were exercised; an untranslated one
  shows in English.
- **User data equal to a UI phrase can be translated.** Names are left alone because
  they are not dictionary keys, and since R22 the bold name cells of the admin tables
  (people, groups, doors, sites, kiosks, review items) and the audit detail column are
  `translate="no"`. Names in drop-downs and inside sentences are not marked: a people
  group literally called "Visitors" would show as 访客 there.
- Traditional Chinese is not provided; `zh-TW` browsers get Simplified Chinese.
