## 3. 其他报错 → 自建的规范

按类别。“落成代码”一栏：✅ 表示已经由脚本或测试强制，⚠️ 表示只是规范、靠我遵守。

### 3.1 Cloudflare Workers 运行时

| 报错 / 教训 | 规范 | 落成代码 |
|---|---|---|
| 一个请求等待另一个请求的 I/O → `Cannot perform I/O on behalf of a different request`，约 11% 请求 500（R20） | 在 Workers 上，等待方轮询标志，不 `await` 别人的 promise | ✅ `store/shared-wait.js` + 单元测试；R22 加了运行时识别测试（见 3.4） |
| Workers 没有 `node:sqlite` / `Buffer`；全局作用域不能取随机数；转发给 Durable Object 前要删掉 content-length | 核心代码只用两边都有的 API | ✅ Worker 冒烟测试 |
| 绕过主入口的路径要先等初始化（`whenReady()`） | 每个新入口都检查 | ⚠️ |
| wrangler 修改文件后会热重载 | 改完等 5–7 秒再测 | ✅ `smoke-fresh.sh` 每次都全新启动 |
| 有些问题只在“全新数据库 + 全新实例 + 满负载”时出现 | 对照实验必须在同样的冷启动条件下做 | ✅ `smoke-fresh.sh`（负载部分见 3.4） |
| D1 导出放在内存里会超出限制 | 一律用 `CompressionStream` 流式压缩 | ✅ 测试 |

### 3.3 编辑与工具

| 教训 | 规范 |
|---|---|
| sed 里的 `\"` 会静默失败 | 多行或带引号的修改用 Python，并且断言锚点只出现一次 |
| 多个经典脚本里的顶层 `const` 会互相冲突 | 前端新文件用 IIFE |
| 正则抽取 JS 字符串太粗糙 | 用分词器（按 `${}` 和 HTML 标签切分） |
| 命令退出码被后续命令覆盖 | `echo exit=$?` 紧跟在命令后面 |
| 日志：`console.error` 在 wrangler 里显示成 `[ERROR]` | 成功信息用 `console.log` |
| npm 版本不同会改写 `package-lock.json` 里无关的字段（R22：删了 51 行 `libc`） | 依赖升级只改目标包那几行，然后 `npm ci` 验证 |
| 永远不要 `require('./server.js')`（会启动服务器） | 测试用 `support/boot.js` |

### 4.2 我的错误有什么规律（以后要防的）

1. **检查写了就以为有效**（日志颜色码、R22 并发检查）。对策：变异验证是强制步骤，不是可选步骤。
2. **数字和时间凭记忆写**。对策：写完再用命令核对。
3. **规则写得太宽**（i18n 的 `^to (.+)$`）。对策：窄规则 + 读实际输出。
4. **优先做新功能，基础防护靠后**（点击劫持到 R22 才补）。对策：每加一个页面或入口，对照 `30-SECURITY-TESTING.md` 的 8 项过一遍。
5. **单文件越来越大**。对策：试点稳定后，第一件重构就是拆 `api-core.js`，按领域拆，每一步都跑全部测试。

### 4.3 能不能自主进化

**能做到的：** 每次出错 → 在本文件加一条规范 → 能写成脚本或测试的就写（R22 的 `agent-recover.sh`、`dev-vars.js`、`smoke-fresh.sh`，以及点击劫持、运行时识别、译文不动点这几个测试），以后换任何会话来做，都会被脚本和 CI 强制执行，不依赖我记得。

**做不到的：**
- 判断“客户真的需要什么”。
- 发现我自己想不到的攻击方式。
- 在真实硬件上验证。
- 替你做商业和法律决定。

这些需要外部输入：试点反馈、渗透测试、真机、你。
