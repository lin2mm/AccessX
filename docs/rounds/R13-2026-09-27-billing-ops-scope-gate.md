## 做了什么

### 1. 站点范围安全门（`test/scope.fuzz.test.js`）
- 自定义角色拥有**全部权限**，但只限健身房一个站点。用它调用路由表里的**每一条路由**，
  带上其他站点的 id，以及"混合"请求体（自己的组/门组，里面放其他站点的门和人）。
- 检查：其他站点的规则、人员、门组、节假日，全租户的时间表和角色，其他站点门上的码和访客，
  其他操作员，租户设置，其他站点的审批——**一样都不能变**；新建的记录不能伸到站点之外。
- 结果：1,551 个请求，0 次越界。
- **变异验证：** 删掉 R12 的门组检查 → 门禁失败（3 处）；删掉"删除人员需其所有组都在范围内" → 失败。
  说明这道门能抓到真实的同类漏洞。
- 已加入 `npm run test:isolation`（CI 合并门槛）。

### 2. 计费运维
- **所有者通知**（告警事件 `billing_problem`，默认开启）：付款失败 → 第 15 天暂停新增 → 第 45 天待关闭 → 付款恢复，每个阶段只通知一次，写入审计。
- **Stripe 计量错误（thin event）：** 取回完整事件，按 `identifier` 定位到具体租户和日期的上报记录，标记错误，开平台问题；取不到时回 502 让 Stripe 重试。
- **平台问题**：计量错误、上报卡住 24 小时、待关闭账户；配置 `PLATFORM_ALERT_WEBHOOK` 后只推送一次。
- **平台账单视图** `GET /api/platform/billing`：最严重的排在前面；可以标记已解决。
- **本月预估：** 用 Stripe 的单价 × 门·天 + 短信段数，税前；所有者卡片显示"每门每月 X"。阶梯价不显示（宁可不显示也不显示错的）。
