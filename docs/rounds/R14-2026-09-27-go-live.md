## 做了什么

### 1. `npm run doctor`：生产配置检查（`doctor-core.js`、`scripts/doctor.js`）
一套检查，三种用法；有错误时退出码为 1，可以放进部署脚本当门槛。

| 用法 | 查什么 | 能看到密钥的值吗 |
|---|---|---|
| `--env-file 文件`（或当前环境变量） | Node 部署的配置 | 能（本地） |
| `--worker` | `wrangler.jsonc`（D1 id、限流、定时任务、`run_worker_first`、Durable Object、日志）+ vars + `wrangler secret list` 列出的**名字** | 不能，只知道"已设置" |
| `--url https://站点 --platform-token …` | 线上站点：`/api/healthz`、`security.txt`、CSP、HSTS；带平台令牌时再调 `GET /api/platform/doctor` | 能，**在服务器上查**，结果只写配置名，不写值 |

报错（不能上线）：弱令牌或演示令牌、匿名只读开着、`SECRETS_KEY` 缺失或不是 32 字节、
`PUBLIC_URL` 不是纯 https 地址或是占位域名、没有 `SECURITY_CONTACT`、开发开关没关、
TTLock 回调密钥太短、邮件/短信只配了一半、`OPERATORS` 或 `AUDIT_SIGNING_KEY` 解析不了、
计费开了但没生效、D1 id 是占位符、缺限流/定时任务/Durable Object。
警告：没接 TTLock、没回调、审计锚点没签名、没邮件、短信没上限、Stripe 测试模式等。

### 2. 修复：Worker 默认允许匿名只读
- **问题：** Worker 上只要 `AUTH_OPEN_READS` 不等于 `0` 就允许匿名只读，而仓库里的
  `wrangler.jsonc` 设的是 `1`。照着部署、忘了改的话，任何人都能看门列表、报表和审计日志。
- **修复：** 两个运行时都改为**显式开启**；只要配置了 `TTLOCK_CLIENT_ID`（接了真实锁）就**一律拒绝**，
  并在日志里说明；`npm run doctor` 把它列为错误。公开演示（没有 TTLock 凭据）不受影响。

### 3. `GET /api/healthz`：给外部监控用
- 不需要令牌，`cache-control: no-store`，不含任何租户数据。
- 数据库连不上 → 503；**数据库落后于代码需要的迁移**（先部署、忘了迁移）→ 503 并说明怎么修。
- `SCHEMA_VERSION` 必须随每个新迁移更新，有测试强制。
- 原来的 `/api/health`（需要令牌的门锁健康：电量、离线）保持不变。

### 4. `npm run backup`：写完备份立刻做恢复测试
- `node`：`VACUUM INTO`，服务运行中也能得到一致的副本。
- `d1`：`wrangler d1 export DB --remote`（本地演练可用 `--local --persist-to`）。
- `verify 文件`：恢复到临时数据库，检查：
  1. 完整性和外键；
  2. 表、索引、触发器与 `migrations/` 一致（审计只追加触发器必须还在）；
  3. 迁移版本；
  4. 每个租户的审计链；
  5. 加密数据用的密钥 id 是否都在当前 `SECRETS_KEY` 里。**这一项最容易被忽略**：
     备份还在但密钥丢了，恢复后每个租户都要重新连接 TTLock、重新配置 SSO。
- `cf:db:*` 脚本改用绑定名 `DB`，生产数据库改名时只改 `wrangler.jsonc` 一处。

### 5. 文档 `docs/12-GO-LIVE.md`
13 步上线清单、doctor 用法、健康检查与外部监控、日志（Workers Logs 保留 3/7 天，
长期保留用 OpenTelemetry / Logpush）、备份策略（D1 Time Travel 30 天 + 每周异地导出；
Node 每晚备份）、三种恢复步骤、**恢复之后要做的四件事**（尤其是：恢复点之后发出的密码还在锁上，
系统已经不认识它们）、演练记录表。

  建议下一轮让冒烟测试顺带触发一次定时任务，并在日志出现 `ERROR` 时失败。
