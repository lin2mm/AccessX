## 做了什么

### 1. 自助开通（`signup-core.js`、迁移 `0022_signups.sql`、`public/signup.*`）
新客户自己开户，不用你手工建租户、发令牌：

1. 登录框旁出现 **Create an account**（只有开通功能打开时才显示）。
2. `/signup`：公司名、姓名、工作邮箱、办公室时区（从浏览器自动带出）、同意条款。
3. 邮件里的确认链接：**24 小时内有效，只能用一次**。
4. 打开链接才真正创建：**一个空的新租户**（不带演示数据）+ 一个所有者操作员，
   所有者密钥**只显示这一次**（复制 / 下载文本文件 / 勾选"我已保存"，没勾选前关页面会提示）。
5. 点 **Open AccessX** 自动登录，接着就是 R11 做好的"开始使用"清单（连接 TTLock → 站点 → 门 → 人员）。
6. 开了计费的话，以后在设置里订阅；没有计费账户的租户就是不限时试用（见 `40-BILLING.md`）。

开关：`SIGNUP_ENABLED=1`，并且必须配好邮件和 `PUBLIC_URL`，否则保持关闭。
`SIGNUP_DAILY_LIMIT`（默认每 24 小时 50 个）、`SIGNUP_TERMS_URL`（条款链接，必须 https）。

### 2. 防滥用与隐私
| 规则 | 做法 |
|---|---|
| 必须确认邮箱 | 不打开邮件里的链接就什么都不创建；填错或冒用别人的地址不会产生账户 |
| 链接 | 只存 SHA-256；一次性（比较后写入，两个标签页同时打开只会建一个账户）；放在 `#` 后面，不进服务器日志和 Referer |
| 同一地址一天超过 3 次 | 回复一模一样，但不再发邮件：没法用它轰炸别人的邮箱，也看不出这个地址是否注册过 |
| 同一网络一天超过 5 次 | 429（IPv6 按 /64 算） |
| 全站每日总量 | 超过 `SIGNUP_DAILY_LIMIT` 返回 429，并写一条错误日志提醒平台 |
| 隐藏字段被填（机器人） | 回复成功，但什么都不存、不发 |
| 邮件发不出去 | 502，明确告诉用户，免得白等 |
| 保留期限 | 申请记录（邮箱、姓名、公司）**7 天后自动删除**，不管用没用过 |

### 3. 平台视图：`GET /api/platform/signups`
最近 100 条申请：邮件是否送达、是否已确认、建了哪个租户；过去 24 小时数量和上限。只有平台令牌能看，永不返回令牌。

### 4. 演示租户一键重置：`POST /api/platform/tenants/:id/demo-reset`
- 请求体必须写 `{"confirm": "<同一个租户 id>"}`，防止手滑。
- 把人员、组、站点、门、时段、规则、凭证、访客等恢复成 `data/acl.json` 的样例数据，一个事务完成（Worker 上在该租户的 Durable Object 里执行）。
- **保留**设置、操作员（演示用的令牌照样能用）、会话和计费。
- **审计链不删**（按设计就删不了）：重置本身记一条 `demo.reset`，`/api/audit/verify` 仍然通过。
- **拒绝（409）**：接了 TTLock 账户、用的是真实锁、或有计费账户的租户。真实客户不可能被误重置。

## 本轮自己踩到并修掉的问题
- **新的日志检查第一次运行就抓到了我自己的问题：** 每次有人注册，我都用错误通道写了一条"tenant created"。
  上线后这会在 Workers Logs 里显示成错误，告警一接上就会半夜叫人。已删掉（注册已经记在审计链和平台列表里）。
  这正是 R14 说的盲区：HTTP 结果全对（31/31），问题只在日志里。
- 登录框的注册链接一开始引用了一个不存在的变量。出错被 `.catch` 吞掉，链接会**永远不显示**，而且不报任何错。读代码时发现并修正。
- Worker 上 `/signup.html` 会 307 跳转到 `/signup`。浏览器一般会保留 `#` 后面的令牌，但不想依赖这一点，邮件链接和按钮都改成直接用 `/signup`（和访客邀请的 `/invite#…` 一致）。
- 测试里三处猜错了返回字段名（`/api/me` 是 `tenant.id`，doctor 结果是 `id` 字段），都是测试本身的问题，不是功能问题。

## 需要你做的（打开自助开通之前）
- 准备一个 https 的服务条款页面，设置 `SIGNUP_TERMS_URL`。
- 邮件服务商（Resend / Postmark）验证发信域名（SPF/DKIM），否则确认邮件容易进垃圾箱。
- 想清楚**试点期间要不要开放自助开通**。我的建议：试点阶段先关着（`SIGNUP_ENABLED` 不设），
  用平台接口手工给试点客户开户；等 Stripe 转正式、定价确定（约 11 月下旬）再打开。
- 如果把公开演示站点给潜在客户点，定期（或每次演示前）调用一次演示重置。
