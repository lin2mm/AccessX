## 做了什么

### 1. 前台平板（`kiosk-core.js`、迁移 `0023_kiosk.sql`、`public/kiosk.*`）
管理员在 **Visitors → Kiosks → Add kiosk** 选站点、起名，页面**只显示一次**配对链接和二维码，
在平板上打开即完成配对。平板首页三个按钮 + 一个手机二维码：

| 按钮 | 访客做什么 | 结果 |
|---|---|---|
| **I'm expected**（有预约） | 输入邀请邮箱 → 勾选到访须知 | 访问标记为"已签到"（时间 + 勾选的是哪一版须知），邮件通知接待人，发 `visitor_arrived` 告警；平板只显示接待人的**名**（"Sarah knows you are here"） |
| **I'm not expected**（临时访客） | 姓名（必填）、公司、邮箱、找谁（选填）→ 勾选须知 | 前台屏幕出现一条"等待中"；如果能唯一匹配到接待人就发邮件给他 |
| **Signing out**（签退） | 输入邀请邮箱 | 结束访问并删除门锁密码（和邮件里的签退链接一样） |
| 手机二维码 | 用自己手机扫 | 同样三个流程，10 分钟有效 |

60 秒没人碰自动回首页；完成后 12 秒回首页。**平板永远不显示门锁密码、访客名单或任何人的全名。**

### 2. 前台屏幕（Visitors 页）
- **Walk-ins waiting**：临时访客列表。**Issue code** 打开平常的建访客表单并预填好，前台照常选门和时段；
  发码、标记签到、关闭这条等待记录在**同一个事务**里完成。**Dismiss** = 不给进。24 小时没处理自动过期。
- 访客列表显示"signed in 09:12 · notice accepted"。
- **到访须知**（Visitor settings，最多 2,000 字）：这是访客勾选的"须知"，**不是 NDA**（没有签名、没有法律审阅）。
- **打印在场访客**（`/visitors-print`）：消防点名用。按站点筛选，两张带勾选框的表：*现在在场*（已签到或已开过门，加等待中的临时访客）
  和*今天预约但还没签到*。只有访客、没有员工。纸上写明含个人信息、用完粉碎。

### 3. 安全设计（详见 `docs/22-KIOSK.md`）
| 问题 | 做法 |
|---|---|
| 平板用什么凭证 | 配对密钥 `kx_…`（256 位），只在配对链接里出现一次，服务器只存 SHA-256 |
| 密钥能做什么 | **只能**调 `POST /api/kiosk`、只限自己的站点。它不是操作员：所有 `/api/*` 都返回 401；**永远不能生成门锁密码、看访客名单、改设置** |
| 平板被偷 | 能做的事和站在前台的访客一样；后台点 **Switch off** 立即失效。"最后在线"每分钟最多写一次 |
| 手机二维码 | 10 分钟、HMAC 签名、平板上每 4 分钟换一个；**没有贴在墙上的固定二维码**（拍照带走 10 分钟后就没用）；手机不能自己续期；关掉平板 = 它发出的所有二维码一起失效 |
| 签到时间窗 | 本站点、访问开始前 **2 小时**到结束；别的站点、别的日子一律"没找到邀请" |
| 邮箱探测 | 签到会暴露"这个邮箱今天在这个站点有没有预约"。**接受**：需要人在现场或持有 10 分钟内的二维码，每 IP 每分钟 120 次，且不透露任何其他信息 |
| 用邮箱签退别人 | 知道访客邮箱、又站在前台的人可以提前结束他的访问。**接受**：只会减少权限，而且有审计 |
| 刷临时访客 | 每台平板每小时最多 30 条（之后 429） |
| 审计 | 只记 id，不记姓名、邮箱、公司；操作者记为 `kiosk:<id>` 或 `kiosk:<id>:phone`；签到记下须知 SHA-256 前 12 位 |
| 个人信息 | 临时访客跟随访客保留天数（默认 30 天）自动抹除；前台可一键 **Erase**；抹除一个访问也会抹除它来源的临时访客记录；演示重置清空临时访客、保留已配对平板 |
| 摄像头 | 仍是 `camera=()`：平板只显示二维码，不扫码 |

### 4. 二维码生成器（`public/qr.js`，无依赖）
浏览器本地生成，链接不经过任何第三方服务。验证方式两种：
**与 Python `qrcode` 参考实现逐位一致**（8 种掩码 × 3 种输入，24/24），并且 OpenCV 能解码（版本 1–10）；测试里固定了输出哈希。

### 5. 注册页 Cloudflare Turnstile（可选）
- 设了 `TURNSTILE_SITE_KEY` + `TURNSTILE_SECRET_KEY` 才启用；服务器向 Cloudflare `siteverify` 验证每个令牌后才发确认邮件。
- 没令牌 / 验证失败 → 400；Cloudflare 连不上 → **503，拒绝放行**（fail closed）。R15 的限流照旧生效。
- **只有 `/signup`** 的 CSP 放开 `challenges.cloudflare.com`；后台、平板和其他页面仍是 `script-src 'self'`。
- `npm run doctor`：只设一个密钥 → 错误；生产用 Cloudflare 测试密钥 → 错误；开了注册却没 Turnstile → 警告。
- 平板不用 Turnstile：配对密钥或 10 分钟二维码已经证明请求来自前台。

## 本轮自己踩到并修掉的问题
1. **二维码验证方法不够硬**：OpenCV 在 8 倍放大下解不出 "HELLO WORLD"（版本 1），4 倍却可以。
   没有盲目改编码器，而是装了 Python `qrcode` 参考实现逐位比对，24/24 完全一致，证明是 OpenCV 检测器的问题。现在两种验证都写进了文档和测试注释。
2. **冒烟测试会误报**：签到要给接待人发邮件，原来的假邮件服务只在注册那一项里启动，其他时间发信失败会写错误日志、触发 R15 的日志门。改为整个冒烟测试期间都开着。
3. **一条路由没测**：临时访客 **Erase** 最初没有测试，补上了（含别的站点前台 404）。
4. **文档写错三处**（写完后逐条对照代码发现）：临时访客列表是 24 小时不是 7 天、密钥哈希不是"加盐"、两句界面提示原文不符。都已改正。
5. **R15 遗漏**：README 迁移列表没写 `0022`，已补。

## 需要你做的
1. **试点硬件**：一台旧 iPad 或安卓平板 + 桌面支架 + 常插电；打开"引导式访问"（iPad）或"屏幕固定"（安卓），关闭自动锁屏。
2. 部署时确认 `PUBLIC_URL` 已设（配对链接和手机二维码需要完整地址）。
3. 在 Visitors 设置里写一段**到访须知**（示例见 `22-KIOSK.md`）；如果要写隐私条款，请让懂当地法规的人看一眼。
4. 以后打开自助注册前，在 Cloudflare 后台免费创建 Turnstile，两个密钥都设上，`npm run doctor` 会检查。
