## 做了什么

### 1. 访问复核（**People → Access review**）

**解决什么问题：** 审计员会问："有没有人定期确认谁还应该有门禁？"（ISO 27001 A.5.18、SOC 2 CC6.2/6.3）。以前系统只有审计日志，回答不了这个问题。

| 环节 | 做法 |
|---|---|
| 复核什么 | 开始时生成清单：每个站点上"有门禁的人"一行（通过人员组或有效的码），每个管理员一行。已停用的人和已过期的人不列入（他们本来就没有权限了） |
| 谁来确认 | 人员行：该站点有 `user.manage` 的经理；管理员行：全站点的所有者。**谁都不能确认自己那一行** |
| 看得到什么 | 经理只看到自己站点的行。用 id 去查别的站点的行，返回 404 而不是 403，不暴露它存在 |
| Keep / Remove | Keep 只做记录，以后还可以改成 Remove。**Remove 立即生效**：离开该站点的人员组，撤销此人在该站点门上的码（有网关的直接从锁上删除；没有网关的标为"待现场删除"）。别的站点的组不动 |
| 提示 | 如果此人还通过"不属于任何站点的组"或"别的站点的组"能开这里的门，结果里写 **STILL opens…**；如果组成员来自目录（SCIM），提示去目录里也删掉，否则下次同步会加回来 |
| 管理员行 Remove | 吊销该管理员，结束其会话（和 Operators → Revoke 同一段代码） |
| 时间线 | 开始时通知有待确认行的人；到期前 3 天提醒一次；过期后通知所有者一次；可设置每 30/90/180/365 天自动开始 |
| 过期处理 | 过了截止日期，所有者可以勾选"没人确认的一律移除"再关闭，每行记为 "not confirmed by the due date"。**管理员行永远不会被批量移除** |
| 证据 | 关闭后的记录进入证据包（是否按时完成、保留/移除/未确认的数量），A.5.18 控制项引用它 |

**并发与失败：** 两位经理同时点同一行，先抢到的生效，另一位得到 409。移除做到一半出错（比如锁厂 API 挂了）时，决定会回滚，可以重试；没能删掉的码会被标记，下次对账时删除。

### 2. 锁上密码对账（**Activity → Passcode sweep**）

读取每把锁上现有的密码，和系统登记比对：

| 结果 | 含义 | 可以做什么 |
|---|---|---|
| issued by AccessX | 系统发的、有效 | 无需处理 |
| not from AccessX | 有人在 TTLock App、安装商或旧系统里设的 | 从锁上删除（需要网关） |
| 同上（已过期） | 已过有效期 | 可删，默认不勾选 |
| revoked in AccessX, still on the lock | 系统撤销了，但没删到锁上 | 从锁上删除，登记改为已撤销 |
| missing from the lock | 系统登记有效，锁上却没有（App 里被删、锁被重置、恢复了备份） | "记为已不存在"：**先再查一次锁**，确认后记为撤销；此人的规则还在，下次对账会重新发码 |

几条规则：
- **永远不显示密码数字。**
- 系统登记的有效码不能在这里删（请到 Codes 撤销）。
- 经理只能对账和删除自己站点的门。
- 每次对账只保存计数。审计日志只写锁号和厂商编号，不写密码名称。

**限制（已写进文档）：** 只能看到锁厂云端的列表。在键盘上用管理员模式直接输入的码、只通过蓝牙删除而没有同步的码，都看不到。

这也补上了 `12-GO-LIVE.md` 里"恢复备份之后要逐把锁核对"那一步：现在点一下就能做。

### 3. 数据保留一览（**Activity → Data retention**）

列出每类数据保存多久、在哪里修改：
- 审计日志：所有者可在这里设 365–3650 天；
- 访客资料：默认 30 天；
- 电池记录、注册申请：固定；
- 复核与对账记录：作为证据保留，只存 id 和计数。

可以直接用于隐私声明和客户的安全问卷。前台角色看不到（403）。

### 4. 批量访客邀请

在"登记访客"里勾选"改为发邀请"后，可以粘贴最多 100 个邮箱，每行一个。所有人共用同一位接待人、同一组门、同一个时间段，每人一个独立链接。

| 情况 | 结果 |
|---|---|
| 共用设置有错（门不在你的站点、敏感门、时间不对） | 整批拒绝，**一封都不发** |
| 单个地址有问题（格式错、重复） | 列出来，其余照发；失败的地址留在框里，改完可以再发 |
| 碰到限流 | 剩下的全部停下，并注明原因 |

批量接口的响应里不返回邀请链接，链接只发到对应的邮箱。

## 本轮自己踩到并修掉的问题

1. **真正的越权漏洞（提交前发现）。** 第一版"从锁上删除"接口只检查锁是否属于本租户，没检查是否属于操作人的站点。健身房经理可以删掉办公室门上的码。新写的测试发现了它，已修复。
2. **站点范围门漏掉了这类问题，现在补上了。** 修好之后，我故意把修复删掉再跑安全门，**结果门照样通过**。原因是这道门只比较数据库前后的差异，而"通过锁厂 API 删码"不改变任何数据库行。现在它还会：
   - 记录发给锁厂的每一个开锁、发码、删码请求，只要碰到操作人站点以外的锁就失败；
   - 检查操作人留下的审计记录里是否提到别的站点的门。

   同样故意删掉修复，两项检查都会报错。这是本轮最有价值的改进：**以后新加的任何碰锁的接口都自动受保护。**
3. **跨租户隔离门的一次误报，背后是真问题。** 租户 B 用租户 A 的站点名去发起对账，系统接受了一个不存在的站点 id，并且存了下来。不算泄漏（B 只是看到自己输入的字符串），但不该接受。现在不存在的站点返回 404。
4. **邮件通知漏了测试。** "每个人只收到自己能确认的行数"原来没有测试覆盖：变异验证时去掉站点检查，测试仍然通过。补了一位有邮箱的健身房经理：他只应被告知 1 行，办公室经理 3 行，所有者 6 行（4 行人员加 3 行管理员，减去他自己那行）。
5. **界面的两个小毛病（jsdom 实测发现）。** 从锁上删除之后，那把锁的整块内容消失，"已删除"的提示也跟着没了；保存审计保留期后，重新渲染把"已保存"冲掉了。两处都已修好。
6. **冒烟测试里读错了字段**（证据包在 `.evidence` 下面），已改。
