# R21：中英文界面（2026-09-27）

**一句话：** 所有 8 个页面（管理后台、前台平板、访客邀请、自助签退、日历确认、注册、证据包、打印名单）都能切换成**简体中文**。浏览器是中文时自动显示中文，右上角（后台在顶栏）有 **中文 / English** 按钮，链接加 `?lang=zh` 可以直接指定语言，比如前台平板。日期按中文格式显示。英文界面的代码路径没有改动。**服务器发出的文字（错误提示、助手回答、邮件、短信）仍是英文**，见“限制”。

## 1. 做法

| 新文件 | 作用 |
|---|---|
| `public/i18n.js` | 翻译引擎：选语言（链接参数 → 本机记住的选择 → 浏览器语言），整句查词典，再按规则匹配带数字或名字的句子；之后页面新渲染的内容也会被翻译（`MutationObserver`），弹窗 `alert/confirm/prompt` 也翻译；标了 `translate="no"` 的内容、代码、输入框不碰 |
| `public/i18n-zh.js` | 中文词典：565 条整句 + 27 条句型规则，术语统一（门 / 门组 / 门码 / 凭证 / 访客 / 接待人 / 双人审批 / 审计记录 …，完整对照表在 `26-I18N.md` §3） |
| `test/i18n.test.js` | 8 个测试，不需要浏览器，每次 CI 都跑 |
| `support/i18n-coverage.js` | 覆盖率工具：启动服务器，用 jsdom 以中文打开全部 8 个页面和后台 6 个标签页，列出还显示英文的字符串 |

**为什么不用“源码里写 key”的常规做法：** 界面是 `app.js` 里约 1,150 行模板字符串，加 7 个小页面。全部改成 `t('key')` 几乎要动每一行，而且离第一个试点只有一周。现在的做法不改英文代码：选英文时引擎只加一个按钮；词典缺一条时显示英文原文，不会显示成 key。代价是整句匹配的局限（见“限制”）。

**日期：** 24 处日期格式化改为跟随语言（`window.axLocale`），中文显示为 `2026/9/27 18:30`。时间仍按门所在时区显示；时区缩写（AEST）保持英文。

## 3. 过程中发现并修掉的问题

- **过宽的句型规则会误译。** 第一版为“移动门”菜单写了 `^to (.+)$` → “到 $1”，结果把清单里的“to do”标签翻成了“到 do”。它藏在“已翻译”的统计里，是逐条读中文输出时才发现的。修法：这类菜单改在代码里按语言拼句（“移到 某门组”），删掉两条过宽规则，“to do”改为“待办”。测试现在要求每条规则都用 `^…$` 锚定。
- **审计详情不应翻译。** 审计记录的详情是服务器写下的原始证据（如 `lock 9002 user u2`），第一版把其中一种翻成了中文。现在详情列标了 `translate="no"`，保持原样。
- **潜在的死循环。** 引擎翻译完会改写页面，这个改写本身也会触发 `MutationObserver`。如果某条译文恰好又能被词典翻译一次（比如译文和原文相同），浏览器会无限循环。测试现在检查“翻译两次 = 翻译一次”，词典里每一条和句型样例都覆盖。
- 星期显示从“星期 1,2,3,4,5”改为 **周一至周五 / 每天 / 周一、周三、周五**。

## 限制（诚实说明）

- **服务器发出的文字仍是英文：** 接口错误提示（原样显示）、助手的回答、邮件、短信、日历邮件、告警 webhook、导出文件。要做需要“租户语言设置”，已放进待办。
- **覆盖率只量了每个页面的默认状态。** 只在操作之后出现的提示（成功横幅、部分校验提示）如果源码里能找到就已翻译，但没有逐个触发验证；漏掉的会显示英文，不会出错。
- **被拆成几段的句子逐段翻译**（例如标签、粗体值、提示分在不同元素里），中文语序可能生硬。重要的已经用句型规则或在代码里按语言拼句。
- **用户数据恰好等于界面词语时会被翻译。** 名字没被翻译只是因为词典里没有它们：一个人员组如果就叫“Visitors”，会显示成“访客”。目前只有审计详情列标了 `translate="no"`，后台表格的名字列还没标（R22 顺手做）。
- **没有请母语审校。** 翻译由我完成，术语统一，但产品文案给客户看之前，建议请一位做过 B2B 软件的中文母语同事通读一遍（`--dump` 能导出全部中文，约 400 条）。
- 没有繁体中文，`zh-TW` 浏览器显示简体。
