## 1. 安全自查（完整表格在 `30-SECURITY-TESTING.md` 末尾）

按外部渗透测试的 8 个范围逐项核对：每项写明有什么证据、还剩什么留给测试人员。

**发现：点击劫持（范围第 7 项）。** 页面的 CSP 里没有 `frame-ancestors`，也没有 `X-Frame-Options`。
**修复：**
- 默认只允许本站嵌入：`frame-ancestors 'self'` + `X-Frame-Options: SAMEORIGIN`。Node 和 Cloudflare（`public/_headers`）两边都加了。注册页加载 Turnstile 时也保留这条。
- 确实要嵌进内网门户时，用 `FRAME_ANCESTORS` 列出允许的来源（只在 Node 上生效）。格式不对就退回只允许本站；设成 `*` 时生产环境的 `npm run doctor` 报错。
- **验证：** 新增 2 个测试。变异验证：删掉 `_headers` 里的规则，测试失败；删掉 Node 里的规则，两个测试都失败。

**顺带核对并更新了文档：**

## 3. R2 备份加密：评估结论

逐表核对一份数据库导出里有什么：
- **明文：** 人员和访客的姓名、邮箱、电话，审计记录，门和时间表的结构。
- **没有：** 可用的门码（只有提示和带密钥的指纹）、操作员和链接令牌（只存 SHA-256）、TTLock / Nuki 令牌和审批码（用 `SECRETS_KEY` 封存，而这个密钥不在导出里）。

结论：**备份泄露是隐私事件，不是开门风险。**
R2 支持客户自带密钥的服务端加密（SSE-C，Workers 绑定的 `put/get` 可以传 `ssecKey`），但本地模拟器不支持，没法测试。加密配置一旦出错，最需要备份的时候就读不出来。所以**不在冻结轮里做，放到部署周在真桶上做**，然后带密钥重做一次恢复演练。在此之前：桶保持私有，不开 `r2.dev`，R2 API 令牌只发给需要的人。写进了 `12-GO-LIVE.md` §5。

## 4. 并发冒烟检查：抓不到目标，如实写明

计划是在 Worker 冒烟测试里加并发检查，防止 R20 的故障复发。加了（冷启动实例上 96 个重叠的读写请求：不能有 5xx，读取全部 200，写入全部成功），然后做变异验证：把 R20 的修复改回旧写法。**检查仍然通过。** 加大到 400 个请求，还是通过。

原因：R20 的故障要在“一次快照重新加载足够慢、很多请求叠在它上面”时才出现，需要约 2,000 人的租户。演示租户太小，重新加载一瞬间就完成了。
**处理：**
- 检查保留，因为它仍能发现并发下的其他错误，但名字和注释改成如实描述，不再称为 R20 回归测试。
- 另外加了一个单元测试，钉住修复的开关：在 workerd 里必须识别为 Workers。变异验证：把开关写死成“不是 Workers”，测试失败。
- R20 故障真正的回归测试仍然是 `npm run load:test`，要在全新的 wrangler 上、约 2,000 人时跑。
