## 核实结果

| 部署脚本的假设 | wrangler 源码里实际是 | 结论 |
|---|---|---|
| `d1 list --json` 输出 `[{uuid, name…}]` | 原样打印 API 对象，`JSON.stringify(dbs, null, 2)`，`--json` 时不打印横幅 | ✅ 字段对。**弱点：** 旧解析从第一个 `[` 开始，如果前面有 `[WARNING]` 一类的行就会解析失败。已改为逐行尝试 |
| 构建里跑迁移不会卡在确认提示 | 没有终端时，确认提示的回退值是“是” | ✅ |
| `d1 create` 只建库 | 建完会问“要不要帮你写进配置文件”；没有终端时回退“否” | ⚠️ 手动在终端运行可能改写 `wrangler.jsonc`。**已加 `--update-config=false`**，并用真 wrangler 验证过这个参数能被接受 |
| 部署输出里第一个 workers.dev 地址就是 Worker 的地址 | 目标地址在 `Deployed <名字> triggers` 之后逐行打印 | ⚠️ 已改为优先取这一行之后的地址 |
| **（R23 文档）** Worker 名字和配置不一致，构建会失败 | Workers Builds 会传入控制台上的名字：wrangler **警告后照样用控制台名字部署**，然后 Cloudflare 开一个 PR 改 `"name"` | ❌ **R23 文档写错了**，已更正 13 号文档 §2 第 1 步和 §4 |
| Durable Object 迁移 | `wrangler.jsonc` 已有 `new_sqlite_classes: ["TenantWriter"]`；它不存数据（数据都在 D1），改名不丢数据 | ✅ |

**另外两处改进：**
- **健康检查分开处理两种失败。** 返回了 HTTP 但不健康 → 构建失败。完全连不上 → 只警告：新注册的 workers.dev 子域名可能要几分钟才能解析，这不能说明代码有问题，而此时代码其实已经上线了。
- **没登录时给一句下一步。** 手动运行却没登录，原来会输出一大段 wrangler 报错，现在只说一句：先 `npx wrangler login`。
