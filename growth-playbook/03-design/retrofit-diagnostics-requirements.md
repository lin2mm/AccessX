# Retrofit 防错设计、自检与安全诊断要求

2026-09-28｜待工程验证的需求规格，不是现有硬件功能承诺。未知项：驱动机械结构、扭矩曲线、传感器、控制板、固件/TTLock 可用遥测、离线能力、适配门型、认证范围。未检查 App 代码，也未据此推断产品能力。

## 1. 先承认边界

旧锁磨损、门扇下垂、锁舌孔错位、装配偏心、电池压降和电机故障可能呈现相似的卡阻信号。**电流高≠确定旧锁坏；电机转完≠锁舌伸出；锁舌伸出≠进入门框；门磁闭合≠安全上锁。**

Nuki 官方 motor-blocked 排查涵盖电池、手动阻力、校准与门调整；SwitchBot 原版 Lock 帮助页提示同轴、负载、拆下区分本机与原锁，并比较开门/关门状态。这些是排查思路，不是我们已经实现自动根因诊断的证明。[1](https://help.nuki.io/hc/en-us/articles/33845417966097-Resolve-the-Smart-Lock-s-motor-blocked-error) [2](https://support.switch-bot.com/hc/en-us/articles/7911260542999-What-to-Do-If-My-SwitchBot-Lock-Gets-Jammed)

## 2. 机械/电气设计先防错，软件后诊断

| 风险 | 候选防错设计 | 验证要求/代价 |
|---|---|---|
| 偏心、角度偏差、轴向顶紧 | 可调同轴支架、有限柔顺联轴器、明确装配基准、限位 | 公差堆叠测试；柔顺不能导致脱落/空转 |
| 夹具松动/粘接失效 | 防转结构、适配键型、锁紧标记、受控紧固方式 | 湿热/低温/老化/振动/反复扭转；不能用更强胶掩盖底材问题 |
| 原锁阻力和卡死 | 限流/限时/热保护、经过验证的扭矩边界、手动优先通道 | 不为完成锁门而不断加力；限制不能妨碍合法逃生 |
| 断电仍需通行 | 机械手动解耦/可用原钥匙方案，按门型验证 | 某些锁芯内插钥匙影响外侧钥匙，必须售前拦截 |
| 错配配件/方向 | 编号适配器、物理防呆、明确左右/行程识别 | 不把错误适配“校准”成正常 |
| 低电压误判卡锁 | 负载电压检测、掉电安全、适当电源储备设计 | 电池类型/低温/老化条件验证；电量百分比不是精确寿命 |
| 断网与升级失败 | 本地安全状态机、签名固件、可恢复升级 | 升级不能让门失去手动开门；不暴露调试后门 |

以上不是最终设计选型。离合、支架和传感器要结合未知机构评审；消防门/逃生门未经专项验证不纳入首发。

## 3. 可观测信号分级

| 信号 | 能直接观测 | 不能据此单独认定 |
|---|---|---|
| 电机电流/负载电压/温度 | 过流、供电下陷、热状态 | 精确扭矩、具体卡在哪里 |
| 编码器角度/速度/用时 | 轴运动、停滞、偏离历史轨迹 | 原锁舌确实运动；齿轮/适配器没打滑 |
| 门磁/距离传感器（如配备） | 传感器判断门近/开，及信号质量 | 门已正确锁住、密封正常 |
| 锁舌传感器（如能安装） | 对应位置的锁舌状态 | 进入扣板且达到安全锁定，除非专门检测 |
| IMU/支架标记变化（可选） | 位置/姿态变化或照片对照 | 精确证明夹具松动 |
| 网关/API 确认/心跳 | 通信链路响应、最后更新时间 | 离线时权限已撤销、机械动作完成 |

电流推算扭矩需要电机常数、传动效率、温度、电压和摩擦标定，不能直接等同测力。若 TTLock 标准接口不提供原始信号，需与厂商确认固件扩展/诊断端点；拿不到则降级为引导排查，不包装成 AI 自动检测。

最小事件字段候选：device pseudonym、型号/固件/适配器、command id、时间及单调序列、负载电压、峰值/RMS电流、起止角/速度/耗时、门状态及置信度、失败类别、重试次数、数据新鲜度。无必要不上传照片/原始地址/访问密码；租户隔离、授权导出、短期保留策略另审。

## 4. 出厂与首次安装建立基线

1. 出厂逐台做空载方向/角度/电源/异常停机检查，序列号绑定测试记录；抽检可靠性不能代替逐台基本功能。
2. 售前照片、尺寸、锁芯功能、安装权限、门扇间隙；不兼容就不卖。Scanner 是辅助筛选，不替代关键机械尺寸与人工复核。
3. 现场有人、门保持打开、手中有可用机械应急方案，先检查原锁手动开关阻力。旧锁本来不顺畅先找合格人员修复，不用电机掩盖。
4. 安装后开门状态校准，检查手动操作与外侧钥匙（适用时）；若安全检查未通过，不进入无人使用。
5. 在有人且保留替代入口的情况下比较关门状态；记录开门/关门曲线差异。阻力大幅增加应检查门框，不靠升扭矩。
6. 完成断网、本地访问、权限、应急步骤和授权人确认，再启用适用自动功能。曲线/阈值按型号与环境标定，不采用所有门通用的电流阈值。

## 5. 诊断树：先分症状，再给概率原因

| 观察组合 | 候选原因（不是确诊） | 安全的下一步 |
|---|---|---|
| 原锁手动开门状态也费力 | 锁芯/锁体磨损、异物或机构问题 | 停用电动尝试，转合格锁匠；不要指导随意注油/拆安全结构 |
| 开门顺、关门费力 | 扣板错位、门下垂、密封压力 | 记录对比，转门窗/锁具人员调整；不能由软件“修门框” |
| 原锁顺、装上后开门也费力 | 偏心、轴向预载、安装件干涉 | 门开着由授权人在场，按批准步骤复核安装；不让远程自动松夹具 |
| 电压负载下跌且运动慢 | 电池/接触/低温供电问题 | 按指定电源替换后重测；仍异常则升级 |
| 电机角度正常但原锁不随动 | 联轴器打滑/脱开、齿轮或测量异常 | 状态显示未知，现场核实；不能显示“已锁” |
| 运动异常且电压正常 | 负载或本机故障 | 仅允许厂商批准的安全隔离检查；人工确认后 RMA |
| 指令无响应、设备状态陈旧 | 网络/网关/云/供电问题 | 不反复发动作；查询新状态与幂等执行结果，现场确认 |
| 基线逐渐恶化 | 电池老化、季节变形、磨损、安装松动 | 趋势预警＋人工复测；不擅自学习成“新的正常” |

拆卸/卸载仅按产品批准流程，由授权人在安全、可通行状态操作。诊断界面分别显示“直接测到的现象”“可能原因”“尚需检查项”，保留“不能确定”。

## 6. 自恢复允许与禁止

**可考虑允许：**不驱动的链路重连；查询最新状态；有安全条件和在场授权下重新校准；在经验证边界内的控制参数调整。具体重试上限由实验确定，发布前不能给出未经验证的通用次数或扭矩值。

**禁止：**无人在场的远程试转以排障；卡死反复加扭矩/来回冲击；绕过电流/温度保护；把掉电一律设为自动解锁；欠费关停基本通行；自动改变租客权限“试试看”；把机械失效宣布为已修复。

状态机建议：UNVERIFIED → READY → DEGRADED → FAULT_STOP → MANUAL_REVIEW → READY。READY 仅代表已通过适用自检，不是“门已锁”。链路状态、轴位置、门状态、锁定确认是独立字段。严重异常后不会因超时自动回 READY；需记录的复核通过。

## 7. 验证矩阵和量产关卡（目标，不是现状）

台架先做正常/磨损模拟/偏心/夹具松动/不同电压温度/开关门阻力/断网/断电/重放指令等故障注入；记录故障真值。覆盖门型、公差、安装人群和环境，单一演示门不够。

- 阶段A：2个明确 SKU/门型，工程台架；证明保护边界和手动应急；任何失控动作/逃生受阻为阻断缺陷。
- 阶段B：20–50扇监督安装门，测实际设置时间、首次成功、误报/漏报和每台支持分钟；这是发现问题，不足以证明罕见故障率。
- 阶段C：扩大到约300扇已批准门型，跟踪30/90日，按门型和用户而非只按平均数分层；预设停止规则和召回/RMA流程。
- 候选商业目标：适配后首装一次成功率≥95%、需专业上门比例≤5%、常规远程支持中位数≤15分钟；超出即重新定价/缩门型，不承诺免安装。小样本即便零故障也不能声称99.9%可靠。
- 检测指标：危险卡阻召回率、误报率、根因分类混淆矩阵、未知率；不能仅用“总准确率”。在300个独立试验中零故障，粗略95%上界仍约1%，且真实门/操作并不必然独立。
- 根因证据不足时允许“未知＋转人工”胜过过度自信；设备在不可证明锁定时不得显示安全已锁。该不变量需专项测试，不靠平均指标通过。

## 8. 对软件渠道的直接经济价值

安装错误减少→退货下降；可导出的诊断包→L1无需懂机械也能正确分流；预警→安排维护而非等夜间失效。必须用试点数据量化。支持成本公式：每台支持次数×每次分钟×人员小时成本/60＋RMA率×每次物流/换机损失。若100台中20台需30分钟支持，按$30/小时就是平均$3/台，尚未算返修；“自装”从来不是支持成本为零。
