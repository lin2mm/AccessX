## 1. 范围与目标口径

首市场美国、英文优先；收费ICP以1–20房源的小房东/物业为主，家庭/租客免费。无智能锁即可用：搬入/搬出交接、指引、应急联系人、任务异常闭环、Scanner。TTLock仅一个许可明确的连接器、两种候选型号；其他硬件生态暂停。短租与长租模板分开，先短租小房东验证商业自动化，再扩长租工作流。

- 注册：累计有效去重个人账号，不含机器人、内部测试、未同意导入的PMS联系人、匿名报告访问。
- 免费MAU：过去30天完成≥1核心任务的去重非付费workspace用户；属于付费workspace的成员不计免费MAU。
- 付费账户：期末有效付费workspace，排除免费试用、未收款意向、退款及硬件购买。一个workspace多成员不多算付费户。
- 注册和付费分母不同，100/5,000不能作为商业试用转化率。商业转化分母用符合资格且试用成熟的workspace。
- 硬件线另外记录需求、兼容、付费订单、净交付；不作为本软件目标达标前置条件。

## 3. 从哪里来：渠道容量与归因

| 渠道 | 年注册目标 | 假设算式 | 首次验证 |
|---|---:|---|---|
| 工具/内容自然访问 | 2,000 | 10,000相关访问×20%注册 | M2完成200相关访问后检查来源与任务完成 |
| 安装商/PMS/物业伙伴 | 1,500 | 5个成熟伙伴×300年注册（晚加入者需更多伙伴补足） | M3每伙伴至少5个真实激活，非只签合作 |
| 许可社区/教学活动 | 1,000 | 5,000相关访问×20%注册 | 每场记录工时、独立注册和30天复用 |
| 工作流邀请/用户推荐 | 500 | 2,500有效邀请×20%新注册 | 不强迫客人装App；测自然自愿接受 |
| 合计 | 5,000 | 唯一首触去重，助攻单列 | 任何未达的量不能用“病毒增长”自动补齐 |

另一个商业漏斗：全年目标600个合格商业workspace试用×约20.3%首次付费=122，扣流失22=100。600需要真实团队/房源需求，不是5000个人账号自动提供。若成熟试用转化只有10%，同样渠道只能约60个新付费，须下调目标或改善产品，不能直接翻倍预算。

## 4. Metrics与闸门

| 指标 | 定义 | 初始目标/动作 |
|---|---|---|
| 激活率 | 注册后7天内发布指引或完成一次交接/异常闭环的人/成熟注册队列 | ≥40%；低则改首次价值，不加功能 |
| 首次价值时间 | 首次有用任务完成-首次开始，按ICP分别算 | 中位数≤10分钟，不包括合法等待对方确认时间 |
| 免费D30复用 | 激活用户第23–37天再次完成核心任务的人数/成熟激活队列 | ≥20%；Scanner一次性用户单列，不以其留存惩罚整个工具 |
| 商业周期复用 | 下次真实入住/交接时继续使用的workspace/有下一次任务机会的workspace | ≥50%；季节性无任务不误当流失 |
| 商业试用转化 | 试用结束+7天内首次付费workspace/成熟合格试用 | 工作目标20%，前30家仅方向性；连续两批低于10%暂停放量 |
| 软件贡献毛利 | 收入-交付成本-免费层分摊-变量渠道佣金 | ≥60%；同时报含交付成本的会计毛利与固定费用 |
| CAC回收 | 全成本付费CAC/每月每账户贡献 | ≤12个月；不是只算广告现金 |
| 支持分钟/活跃workspace | 当月人工支持时间/活跃workspace | 看下降趋势；前期人工服务不得算零 |
| 推荐/渠道质量 | 每伙伴激活、D30、付费与退款 | 不按签约数量奖励 |
| 授权与错误状态 | 越权、跨租户泄露、虚假成功等严重缺陷 | 发现即停相关功能，纠正后复测；零报告不等于零漏洞 |

事件：account_created、workspace_created、guide_published、handover_confirmed、issue_opened/accepted/resolved/reopened、scanner_completed、integration_authorized、automation_confirmed/failed、trial_started、subscription_paid/cancelled。日志不收门码、原始凭据、精确居住轨迹；测量同意与服务必要记录分开。

周一30分钟漏斗与故障，周五30分钟用户/渠道复盘，月末财务与队列。M3/M6/M9决策只有继续/收窄/暂停；安全和预算不让位于月目标。

## 5. 需要多少人？

### A. 现在$0研究验证阶段

创始人1人每周10–15小时；AI辅助材料和分析；无新增雇员。可以研究、沟通合作、用现有免费工具手动验证指引和任务。不能承诺交付完整生产App、24/7门禁支持或硬件量产。AI不是签合同、安全责任或真实客户支持的替代人。

### B. 获批的软件执行团队：约3.5–4个全职当量

| 角色 | 人力 | 职责 |
|---|---:|---|
| 创始人/产品兼伙伴销售 | 1.0 FTE | 定位、需求、TTLock/PMS商务、前20家客户和预算 |
| 全栈/后端工程师 | 1.0 | 租户/权限/任务/API/计费/日志/运行维护 |
| 前端/PWA与集成工程师 | 1.0 | 免费工具、Scanner问卷、交互、连接器；原生App后置 |
| 客户成功/增长 | 0.5，M6后视工单增至1.0 | 上线协助、内容、伙伴培训、客服与队列 |
| 设计/QA/安全/法律 | 外部专项合计约0.25–0.5 | 原型、测试、安全评审、隐私/合同；需预算，不默认免费 |

核心3人+兼职/专项合计约3.75–4.0 FTE，可能分布在5–7个实际人员。创始人不具备工程技能时，不能假设其兼任两名工程师。只配1–2人则收窄到无设备PWA、手工CSV与少量客户，延长目标时间，不暗中保留全部范围。

### C. 硬件不是上述团队顺手完成

硬件另需明确责任人及机械/电气/固件/测试、供应商质量、认证与安装资源，可采用已合规OEM合作但仍需尽调。最小试点也建议0.5–1个硬件/供应链项目负责人，加按阶段专家服务；不是量产总人力报价。自研新锁从零开始不可用软件目标倒推交期。

## 6. 需要多少钱与效果预期？

**本轮仍$0支出。以下是申请预算模板，不是已获批准或供应商报价。**

人力示例按所在地/外包模式自填全成本：3.5 FTE×$3,000–6,000/月×12=$126k–252k；专项安全/法律/设计QA $8k–20k；运行/工具/平台/借测不足时样机 $4k–12k；渠道验证/奖励 $2k–6k。小计$140k–290k，建议再留15%缓冲约$161k–334k。高成本地区招聘可能明显更高。兼职/创始人未领薪也记录机会成本，专项与全职岗位不能重复计费。**不含硬件研发/模具/认证/库存，不含自有域名等未批准购买。**

若预算远小于此范围，采用A阶段或缩小团队范围；不可承诺同样速度和完整产品免费完成。

年末收入假设：80个Ops×$19+20个Team×$59=$2,700 MRR，ARR run-rate=$32,400，不是首年收入。用每月平均在订账户（期初/期末平均）约410个账户月，若全年加权ARPA固定$27，则首年软件收入约$11,070；套餐结构晚期提升则更低。贡献毛利60%约$6,642，显然不足支付完整团队。100付费是PMF学习目标，不是公司盈亏平衡目标。

若每月固定费用$12,000、每账户贡献$16.2，则约741付费账户才仅覆盖固定费用，尚未加获客增长开支。可以提高真实ARPA、缩小成本或延长发展周期；不能通过阻止家庭开门强迫收入。

## 7. 依赖与可替代路线

- TTLock谈不成：无锁软件继续，不改用未经许可方式；硬件控制目标顺延。
- PMS未授权：手工/CSV用于基础流程，iCal仅排期提示；不承诺统一平台消息。
- 预算未批准：保持手动验证，月表不启算。
- 安全评审未通过：暂停写设备能力，只保留安全的非设备流程。
- M6低于15付费且没有改善队列：停止新增连接器和原生App，集中一个闭环。
- 硬件工程/法规不过关：不预售，不影响软件独立购买。
